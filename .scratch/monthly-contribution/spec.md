# 每月入金與定期定額調整

Status: ready-for-agent

## Problem Statement

在真實投資情境中，多數人除了期初的一筆初始資金外，每個月還會有一筆固定可投資的現金流入（例如薪資結餘）。目前的模擬器只有開局一次性的初始資金，既無法模擬每個月持續新增資金的操作節奏，既有的「定期定額」比較基準也只是把初始資金拆成 12 期、每隔 20 個交易日買完就停止，與一般投資人認知中「每個月固定拿一筆新錢持續買進」的定期定額不符，也無法檢驗主動操作在有持續現金流下的長期績效。

## Solution

在開局設定中於「初始資金」之外新增「每月入金」（預設 10,000 元），讓使用者從次一個日曆月的第一個交易日開盤起，每個月固定獲得這筆新增現金供下單運用。兩個比較基準也同步貼近真實規則：買進持有僅使用初始資金於開局第一天全數買進，之後不領取每月入金也不再買賣；定期定額則不包含初始資金，從第一個即時交易日開盤起，每個日曆月的第一個交易日開盤固定投入每月入金買進（單月買不完的零頭餘額滾入下月合併買進）。三方皆以各自截至當下的累計投入本金計算累計投入報酬率，使長期投資與分批攤平的效果能客觀並排比較。

## User Stories

### 開局設定與邊界

1. As a 使用者, I want 在重新開局設定中看到「每月入金」欄位（預設 10,000 元）, so that 我能設定每個月固定新增多少資金投入練習。
2. As a 使用者, I want 將「每月入金」設為 0 元, so that 我仍可進行不追加每月資金的純初始資金模擬。
3. As a 使用者, I want 將「初始資金」設為 0 元並搭配大於 0 的「每月入金」, so that 我能練習從零本金開始、純靠每月定期存錢投資的情境。
4. As a 使用者, I want 系統阻止同時將初始資金與每月入金都設為 0 元並顯示錯誤提示, so that 一局至少會有可用資金而不會完全無法交易。
5. As a 使用者, I want 每月入金和初始資金一樣在開局後於局中無法修改, so that 一局的條件從頭到尾維持一致。

### 使用者每月入金發放

6. As a 使用者, I want 開局當月僅保有初始資金、從次一個日曆月的第一個交易日開盤起領取第一筆每月入金, so that 我開局第一天的可用現金就等於我設定的初始資金，不會開局當下就多出一筆錢。
7. As a 使用者, I want 在後續每個日曆月的第一個交易日開盤自動獲得每月入金, so that 我的現金帳戶會隨時間推進固定增加可買進資金。
8. As a 使用者, I want 開局預產的 250 個歷史交易日不發放每月入金, so that 進入即時交易日之前不會憑空累積現金。
9. As a 使用者, I want 當模擬期限最後一個交易日剛好是該日曆月的第一個交易日時，開盤仍照常發放每月入金, so that 最後一個正常交易日的權益不受影響，直到收盤到期才停止。
10. As a 使用者, I want 在日曆月首個交易日開盤時暫停，即可立刻使用剛入帳的每月入金下市價單買進, so that 我能和定期定額在相同的開盤時點進行決策。

### 比較基準規則

11. As a 使用者, I want 「買進持有」僅使用初始資金在第一個即時交易日開盤全數買進、之後不領取每月入金也不再買賣, so that 我能對照單筆期初投入與持續入金策略的差異。
12. As a 使用者, I want 當初始資金設為 0 元時，買進持有不買進且報酬率維持 0%, so that 零初始資金時不會出現異常數值。
13. As a 使用者, I want 「定期定額」不包含初始資金，且從第一個即時交易日開盤起即投入第一筆每月入金買進, so that 定期定額從開局第一個月就有部位與報酬率表現，不會在開局當月空白。
14. As a 使用者, I want 定期定額在後續每個日曆月的第一個交易日開盤再投入每月入金買進，直到模擬期限到期為止, so that 定期定額真正達成每月固定投入相同金額。
15. As a 使用者, I want 定期定額單月買不完的零頭現金保留在定期定額現金中並滾入下個月合併買進, so that 零頭不會長期閒置浪費，且當股價高於單月入金金額時也能累積數月後買進 1 股。
16. As a 使用者, I want 當每月入金設為 0 元時，定期定額不買進且報酬率維持 0%, so that 定期定額行為在各種設定下邏輯單一一致。

### 部位、損益與累計投入報酬率

17. As a 使用者, I want 在部位面板看到我的「累計投入本金」與「總損益」, so that 我清楚自己到目前為止總共投入了多少錢，以及扣掉本金後實際賺賠多少金額。
18. As a 使用者, I want 我的操作與兩個比較基準都改以各自的「累計投入本金」為分母計算報酬率, so that 單純每月存錢不會被誤算成投資獲利，且能真實反映定期定額攤平成本的優勢。
19. As a 使用者, I want 總損益等於總資產減去累計投入本金（亦等於已實現損益加上未實現損益）, so that 我入金後不會讓帳面損益暴增，帳務數字彼此完全對得起來。
20. As a 使用者, I want 資產曲線窗格的三條線隨時間與每個 tick 即時呈現三方的累計投入報酬率, so that 我能直接觀察不同投入方式在市場波動下的績效消長。

### 存檔與讀檔

21. As a 使用者, I want 每月入金設定寫入存檔，關掉瀏覽器重開後所有現金入帳、累計投入本金與比較基準買進紀錄都完全相同, so that 長期模擬進度能精確延續。
22. As a 使用者, I want 讀取舊版（未含每月入金機制）的存檔時看到「行情引擎已更新，需重新開局」的提示, so that 不會用新舊混合的規則重算出錯誤的帳務與比較基準。

## Implementation Decisions

- **推翻與修訂既有規格**：
  - 取代初始模擬器規格中「定期定額每 20 個交易日投入初始資金十二分之一、投完 12 期停止」的定義，改為「不包含初始資金，自第一個即時交易日開盤起每個日曆月的第一個交易日開盤投入每月入金、零頭滾入下月合併買進、直到模擬期限到期」。
  - 取代既有「比較基準共用同一初始資金」與「報酬率以初始資金為分母」的假設，改為三方各有獨立的累計投入本金，並以累計投入報酬率計算三方報酬率。
  - 修訂初始資金驗證規則：初始資金與每月入金皆允許為大於等於 0 的數值，但兩者總和必須大於 0。
- **架構與既有決策相容性**：
  - 嚴格維持「存檔以種子重算行情」（ADR-0001）：每月入金的撥入與定期定額的自動買進皆僅讀取交易日日曆日期與當下開盤價，完全不消耗亂數、不影響價格模型與 K 棒產生。
  - 報酬率計算依循「有現金流時採累計投入報酬率」（ADR-0002），不採用時間加權報酬率（TWR）或內部報酬率（MWR / XIRR）。
- **模擬核心（headless）新增與調整責任**（沿用現有唯一的測試接縫）：
  - 開局設定新增每月入金參數，預設為 10,000，允許大於等於 0；初始資金預設維持 1,000,000，放寬為允許大於等於 0。
  - 在每個即時交易日開盤時（前一交易日收盤資產曲線點紀錄完畢、當日開盤價確立後），判定該交易日所屬日曆年月是否與前一交易日不同（亦即為該日曆月的第一個交易日）：
    - 若為第一個即時交易日：買進持有以全部初始資金（若大於 0）全數買進；定期定額若每月入金大於 0，撥入每月入金並買進。使用者此日不領取每月入金。
    - 若為後續每個日曆月的第一個交易日：若每月入金大於 0，使用者現金與累計投入本金皆增加每月入金；定期定額現金與累計投入本金皆增加每月入金，並以定期定額帳戶內全部可用現金盡量買進（無條件捨去至整股並扣除手續費）。
  - 帳戶狀態查詢擴充回傳「累計投入本金」與「總損益」（總資產減去累計投入本金）；比較基準帳戶查詢擴充回傳各自之「累計投入本金」。
  - 報酬率計算函式改以 `(總資產 − 累計投入本金) ÷ 累計投入本金` 計算三方數值；當任一方之累計投入本金為 0 時，該方報酬率安全回傳 0。
  - 存檔開局設定納入每月入金欄位，並將引擎版本號遞增為第 4 版，拒絕舊版存檔。
- **介面層調整**：
  - 重新開局面板於初始資金旁新增「每月入金」數字輸入欄（預設 10,000，最小值 0），初始資金輸入欄最小值調整為 0；確認開局時驗證兩者皆為有效非負數且不同時為 0。
  - 部位面板新增顯示「累計投入本金」與「總損益」欄位。
  - 資產曲線與績效面板直接顯示模擬核心輸出的三方累計投入報酬率，其餘圖表互動、指標與存檔時機維持不變。

## Testing Decisions

- **好的測試只驗證外部行為**：一律透過模擬核心的公開介面（建立一局、推進 tick、委託市價單、讀取帳戶／比較基準／報酬率／資產曲線／存檔與讀檔）驗證結果，不測試內部輔助函式或私有變數，並使用固定種子確保測試可重現。
- **唯一測試接縫**：沿用現有的模擬核心（headless 模組），不新增其他測試接縫。
- **測試涵蓋行為**：
  - **日曆月觸發時點**：驗證起始日為月初或月中且跨週末時，定期定額於第一個即時交易日開盤即買入第 1 筆，使用者於次一個日曆月的第一個交易日開盤才領到第 1 筆每月入金；預產歷史期間兩者皆不觸發；模擬期限最後交易日若逢日曆月首日開盤照常觸發。
  - **定期定額餘額滾存**：驗證買進後剩餘的零頭現金保留並在下個月合併當月入金一起買進；在股價高於單月每月入金的條件下，累積數個月現金後可順利買進 1 股。
  - **買進持有獨立性**：驗證買進持有僅於第一個即時交易日開盤投入初始資金，後續月份即使發放每月入金也不增加現金或股數。
  - **累計投入報酬率與損益恆等式**：驗證三方皆以各自的累計投入本金為分母計算報酬率，且使用者領取每月入金前後「總損益 = 總資產 − 累計投入本金 = 已實現損益 + 未實現損益」恆等成立。
  - **零元邊界條件**：驗證每月入金為 0 時定期定額不買進且報酬率為 0；初始資金為 0、每月入金大於 0 時，買進持有報酬率為 0、使用者首月現金為 0 並於次月首個交易日領到第一筆入金，資產曲線與報酬率不出現 `NaN` 或 `Infinity`。
  - **存檔與讀檔**：驗證包含每月入金與多次跨月交易的存檔以種子重算讀回後，帳戶、比較基準、報酬率與資產曲線完全一致；引擎版本號為 3 或缺少每月入金設定的舊存檔被拒絕讀檔。
- **測試工具與先例**：沿用 Node 內建的 `node:test` 與既有的模擬核心測試檔作為先例。
- **不寫自動化測試的部分**：重新開局面板的「每月入金」輸入框與驗證提示、部位面板新增的「累計投入本金」與「總損益」顯示、資產曲線與手機版版面，維持以瀏覽器實際操作檢查。

## Out of Scope

- 每月入金依年數或通膨自動調漲（維持每期固定金額）
- 局中修改每月入金金額、暫停或恢復入金
- 讓使用者自訂每月入金發放日（例如固定每月 15 日）或改回每 20 個交易日週期
- 主動出金／提領現金功能
- 以時間加權報酬率（TWR）或年化內部報酬率（MWR / XIRR）作為主報酬率口徑
- 舊版（引擎版本 3 及更早）存檔的相容性自動遷移
- 實際實作投資報告覆蓋層頁面（投資報告本身另依其規格實作）
